I'm very happy with my Astro experience so far. Though I'm not the most adept JavaScript dev I've been able to stumble my way through building out custom collections, parsing data via JSON and MD files, getting SASS working (a work in progress, that is), leveraging Astro's built-in \<Image /> component, implementing a few npm packages (yay good documentation!), and a lot more.

While I've always had a *lot* of ideas when it comes to stuff I'd like to build on the web, it's been challenging to get some of those ideas to seamlessly come to life. Every project has stumbling blocks (lord knows I've had a few), but I've not been able to resolve those issues as smoothly as I have while working with Astro, and that's something which has really made the experience special for me so far.

I would say this has been due to a combination of a few things. First, the Astro docs are excellent. Though I'm still wrapping my brain around a few concepts in the framework, their basic tutorials really do give you all you need to get a fresh blog up and running with very little JS experience. You're also writing Typescript (for the most part), which makes JS a lot more accessible for standard web development purposes.

Second (a two-parter), the Astro community on Discord is extremely friendly and helpful. Can't say that for every development community. This also presents itself through the relevant blog posts I'm finding when I search for Astro resources. The framework has only been around for 3 or 4 years AFAIK but there are plenty of well written how-tos out there, documented in a helpful way, and easy to find despite the morass that is Google search these days.

Third and finally, I'm having fun with it. There have been challenges and there will continue to be, but getting to the root of those problems and solving them has been a genuinely engaging learning experience. I step away from working on something for a bit when I hit a wall. Three things can happen when I start work again:

1. I can't solve the problem, so I put it aside again
2. I can't solve the problem and I'm frustrated about it, so I scrap what I'm working on
3. I solve the problem

With most projects, I usually end up firmly with outcome 1. After enough troubleshooting, I get to number 2. With Astro, I'm continually amused that I end up solving my issue on the first revisit. There are exceptions, I've scrapped a few things and started over, but overall I'm encouraged to stick with this as I've been able to figure things out without exceeding amounts of frustration.

If that's not a mark of a good framework, I don't know what is.
